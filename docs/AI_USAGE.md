# AI 使用与人工验证记录

## 当前结论

本项目在选题、方案收敛、代码实现、界面实现、测试与文档整理中使用了 Codex。运行时的 OpenAI-compatible LLM 路径也已经实现，但当前环境没有配置真实 `LLM_API_KEY` 与 `LLM_MODEL`，所以本地实测结果使用的是明确标注的确定性模板。

这两类 AI 使用必须区分：

- **开发期 AI**：Codex 辅助生成和修改仓库内容，所有结果由代码检查、测试、实时请求或人工页面操作复核。
- **产品运行时 AI**：可选的 Evidence Pack 归纳层；当前只用假客户端覆盖了接口成功/失败路径，尚无真实模型调用记录。

当前同样没有扶摇鉴权记录、生产 URL、远程仓库或可回填的 commit。

## 重要人工修正

### 1. 盘中流动性不做错误同比

问题：实时日 K 在盘中会包含当天尚未完成的累计成交额。如果直接用它除以前 20 个完整交易日均值，会系统性低估流动性。

修正：当最新 K 线日期等于上海时区当天且时间早于 15:05 时，`M_LIQUIDITY_AMOUNT_RATIO` 返回 `null`，显示“盘中未完成”，不生成对应 Evidence。2026-09-28 11:36 CST 的实时烟测确认了该行为，页面数据健康度相应为 `partial`。

### 2. 置信度覆盖率以题目七维为分母

问题：如果覆盖率只在 MVP 已实现的四个维度内部计算，四项齐全会显示 100%，从而掩盖估值、情绪和事件尚未覆盖的事实。

修正：覆盖率固定为“可用维度数 / 7”。固定 fixture 中四项均可用时为 `4/7 = 0.5714`；上述盘中实时结果因流动性缺失为 `3/7 = 0.4286`。同时保留全 A 宽度代理最高 84 分、核心缺失/过期/演示数据封顶规则。

### 3. 实时连接与后备来源不做伪装

问题：公开行情域名在当前网络下出现过 IPv6 路径不稳定；候选新浪 `hs_a` 接口无论请求多大样本实际最多只返回 100 行，不能代表全 A 宽度。

修正：服务端设置 `ipv4first`，并删除不可靠的新浪后备。最终宽度实时源只有东方财富全 A 涨跌分布；核心实时数据失败时，默认 `auto` 会保留错误并显式切换到带来源与时点的真实历史快照，绝不把 100 行截面或构造数据包装成正常宽度。

### 4. 快照降级保留时间语义

问题：只有实时链路时，公开接口临时失败会让演示完全不可用；但静默使用旧数据又会把历史截面误认成当前行情。

修正：用同一公开数据链路抓取 `data/market-snapshot.json`，原始抓取时间为 `2026-09-28T03:24:04.494Z`，市场日期为 `2026-09-28`。`snapshot` 模式和 `auto` 降级都会把模式、来源、抓取时间与实时错误保留在结果中。该快照为盘中数据，仍触发 74 分置信度上限；2026-09-28 的强制快照烟测返回 `snapshot`、3 个来源、`coverage=0.4286` 和 `confidence=74`。

### 5. 风格追问使用同一研究时点

问题：连续两次独立实时请求可能跨越行情更新，导致主研判与风格追问引用不同截面。

修正：浏览器为研究会话生成随机 ID，服务端按“会话 ID + 20/60 日窗口”缓存最近一次成功 `MarketSnapshot` 两分钟。2026-09-28 的 60 日主研判与随后风格追问返回相同 `fetchedAt`，执行轨迹显示“复用同一研究会话”；自动化测试进一步确认不同会话和不同窗口不会串用缓存。

## 产品运行时 AI 边界

### 已实现的可选 LLM 能力

- 使用 OpenAI-compatible `POST /chat/completions`。
- 输入仅包含受限 ResearchPlan、程序状态和白名单 Evidence Pack。
- 输出只允许 `headline`、`mainConflict`、`inferences`、`uncertainties` 的严格 JSON 结构。
- 每一项必须引用本次 Evidence Pack 中存在的 ID。
- 模型解释不得包含阿拉伯数字，避免把未核验数字带入结果。
- 预测、买卖、加减仓、收益承诺等表达会触发拒绝。
- 超时、HTTP 错误、坏 JSON、Schema 不匹配、未知 Evidence ID 或合规失败均使用确定性模板，并把原因写入执行轨迹。

### 始终由确定性程序负责

- 问题范围与合规前置检查。
- 数据拉取、Schema 校验、清洗、单位处理和时间判断。
- 趋势、宽度、风格和流动性指标计算。
- 市场状态矩阵、置信度、封顶和状态切换条件。
- Evidence → Metric → Source 完整性及引用白名单校验。
- 无 LLM 时的完整可用解释。

AI 不得创造来源、指标、事件、数字或 Evidence ID，也不得在核心数据缺失时补出正常结论。

## 人工验证原则与结果

### 合规措辞

输入“明天涨不涨，买什么股，几成仓？”时，接口返回结构化 `COMPLIANCE_BLOCKED`，拒绝个人化交易/仓位建议，并给出安全的市场状态研究问法。当前输出使用“截至某市场日”“当前状态”“需要重新判断的条件”，不把置信度表达成上涨概率。

### 引用和数字

页面结论中的 Evidence ID 可以打开追溯抽屉；抽屉显示关联 Metric、公式、SourceRef、市场日期、抓取时间、原始字段与请求参数。自动化测试覆盖不存在的 Source ID、未知 inline Evidence ID 和运行时未知引用。

### 缺失与降级

`null`、空数组和除数异常不会转换为 `0`、`NaN` 或 `Infinity`。`live` 模式下趋势或宽度缺失时状态为“证据不足”；默认 `auto` 模式则在核心实时数据缺失时显式切换到真实历史快照，并保留原始错误。非核心指标缺失时保留核心结论并将健康度标为部分可用。盘中流动性是本轮实际验证的非核心缺失案例。
